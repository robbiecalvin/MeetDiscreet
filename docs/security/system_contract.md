# MeetDiscreet — Engineering Boundaries

This inherited framework document describes engineering expectations.
It is not executable enforcement, a model guarantee, or a source of authority
above [root AGENTS.md](../../AGENTS.md). Follow the actual environment
instruction hierarchy and [repository precedence](../strategy/instruction_priority.md).

- Execute the authorized scope and preserve unrelated work.
- Do not invent APIs, integrations, test results, or deployment status.
- Protect credentials, private media, messages, and personal data.
- Enforce production permissions and financial authority on the backend.
- Preserve approved requirements, prices, proposals, and unresolved decisions.
- Obtain explicit authorization for destructive or irreversible operations.
- Validate relevant outcomes and report concrete failures and limits.

Use the [workflow guide](../workflow/workflow_engine.md) proportionally.
Clearly identified drafts, prototypes, and synthetic fixtures are permitted
when requested. Do not represent them as functioning production integrations.

Resolve routine implementation details within approved scope. Ask only for
information necessary to dependent work and continue useful independent work.
When capabilities or access prevent completion, explain the specific blocker
and preserve a useful continuation point in [the roadmap](../next_steps.md).

No self-awarded score, framework stage, or passing task establishes release
readiness. Refer to [launch acceptance](../development/launch_acceptance.md)
and Robbie’s release decision.
