# MeetDiscreet — Context Resolution

Start with [root instructions](../../AGENTS.md),
[project context](../project_context.md), and the current-work section of
[the roadmap](../next_steps.md). Read README.md for required orientation
and reuse unchanged context already loaded in the session.

Follow [selective context loading](./context_and_rate_limits.md): inspect
filenames and targeted searches, then read affected files and relevant
requirements. Do not load every framework document for every task.

Resolve conflicts using [instruction priority](../strategy/instruction_priority.md).
Relevance does not override authority. Verify current repository state rather
than treating old progress notes as proof of implementation or deployment.

Use these established sources:

- Product context: [project_context.md](../project_context.md).
- Progress and handoffs: [next_steps.md](../next_steps.md).
- Confirmed decisions, proposals, and open questions: [decisions.md](../decisions.md).
- Product rules: [product specification](../product/product_spec.md) and relevant domain documents.
- Shared visual rules: [design system](../design/design_system.md).
- Visual feedback: [design memory](../design/design_memory.md).
- Page-specific decisions: [page briefs](../design/page_briefs/README.md).

Keep proposals and hypotheses distinct from confirmed decisions. Ask for
missing information only when it blocks dependent work, and continue useful
independent work. Preserve the current objective, explicit corrections,
verification results, and next action when handing off; exclude secrets.
